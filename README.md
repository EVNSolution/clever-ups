# CLEVER UPS

국내 배송사 UPS의 기존 Fleetune 시스템을 재개발하는 고객 맞춤 SI 프로젝트입니다.
이 문서는 최신 현황만 적습니다. 지난 일의 기록은 Git 이력과 PR에 있습니다.

## 현재 상태

동작하는 것:

- 웹(`apps/web`): 로그인, 가입(개발 관리자가 준 가입 코드와 휴대폰 인증), 센터 입장 코드, 접근 신청과 재신청, 개발 관리자의 승인·거절·회수.
- 웹: 좌측 메뉴 레일(관리·배차·모니터링·계정). 모니터링 > 운행 현황은 그날 전송된 배차를 기사별로(완료/전체·예외·마지막 위치 시각) 보여 주고, 지도에 기사 위치(트럭 배지)를, 기사를 고르면 진행 타임라인과 경로를 보여 줍니다. 1분마다 다시 읽습니다. 지도(MapLibre, OpenFreeMap) 위의 기사·주문·권역 탭, Detail, 센터 선택, 운영일 선택(달력). 달력 아래 상태 Pill이 그날 주문 수·위치 미확정·기사 미배정을 보여 주고, 누르면 주문 탭이 그 필터로 열립니다. 관리 메뉴의 지도 왼쪽 위 "권역 보기 | 주문 보기" 토글로 권역 칸과 주문 핀 중 하나를 그립니다(권역·주문 탭을 고르면 따라 바뀜). 지도에서 주문 핀에 마우스를 올리면 고객명·회사명·주소1(원문)·주소2(한글) 카드가 뜹니다. 주문 탭의 "주문 전체 셀 보기"는 그날 주문을 전체 화면 표로 보여 주고, 관리자·개발 관리자는 칸을 고쳐 저장합니다(Ours24에는 쓰지 않음, 고친 칸 표시). API 상태는 연결이 실패할 때만 보입니다. 개발 관리자는 레일의 "계정 > 승인"에서 승인·입장 코드를 다룹니다.
- 배차(권역 배차): 그날 주문을 권역의 담당 기사에게 나누는 것이 기본입니다. 지도의 "배정 | 조정"으로 그 날만 바꿉니다. 배정은 기사 없는 권역을 여러 개 골라 기사를 정하고, 조정은 기사 색으로 칠한 권역을 다시 주거나 핀 하나를 다른 기사로 옮깁니다. "권역 | 세부권역"으로 단위를 고르고, 되돌리기·초기화가 있습니다. 조정에서는 기사별 바깥 경계를 기사 색으로 진하게 그리고, 확대하면 세부권역 경계가 점선으로 보입니다. 배차 저장이 그 날의 초안이 되고, 그 날을 다시 열면 저장된 배차에서 시작합니다. 배차 기사·배정 주문·기사당 평균, 미할당 업무·미할당 기사를 보여 줍니다. 기사를 고르면 경로 엔진이 방문 순서를 계산해 Detail에 세로 타임라인(순번·도착 예정 시각·누적 거리)을, 지도에 도로 경로선과 핀 순번을 보여 줍니다. 출발 시각을 고를 수 있습니다. 출발지는 센터 차고지이고(서버가 `depot_address_ko`를 V-World로 찾음), 찾지 못하면 첫 주문입니다. 결과는 저장하지 않습니다.
- 주문 목록: 제목은 주소입니다(수취인 이름·세부 주소는 목록에 없음). 한글 주소를 먼저, 보낸 사람이 쓴 원본 주소를 그 아래 흐리게 보여 줍니다. 한글 주소가 없으면 원본만 보이고, 관리자·개발 관리자는 주문 상세에서 한글 주소를 직접 입력합니다("한글 주소 없음" 필터). 입력하면 서버가 V-World로 바로 위치를 찾아 지도에 찍습니다. 못 찾으면 위치 없이 대기열에 남고 다음 지오코딩 실행 때 다시 찾습니다. 권역에 기사가 배정되어 있으면 주문에 그 기사가 제안으로 붙고, "기사 미배정" 필터로 남은 주문을 봅니다.
- 탭별 지도: 주문=주문 마커만, 기사=기사에게 배정된 권역의 주문만, 권역=권역 칸과 주문 수만. 주문은 본 날짜를 짧게 기억하고 앞뒤 날짜를 미리 읽어 날짜 이동이 빠릅니다.
- 센터·기사·담당 권역: 개발 관리자가 레일의 "계정 > 센터"에서 센터(코드·이름·차고지 주소)를 만들고 고칩니다. 관리자·개발 관리자는 기사 탭에서 기사 ID로 기사를 추가하고, 권역 Detail에서 담당 기사를 지정합니다(기사 이름·전화번호는 받지 않음).
- 권역 편집(관리자·개발 관리자): 권역 탭의 "권역 편집"이 Detail에 열립니다. 권역은 시 경계, 세부권역은 상위 권역 안의 행정동 경계를 지도에서 눌러 고르고 저장합니다. 서버가 겹치는 부분을 잘라 냅니다. "그리기"로 지도에 꼭짓점을 찍어 직접 그릴 수도 있습니다. Snap(기본 켜짐)은 보이는 경계·권역의 꼭짓점과 선분에 붙입니다.
- 권역: 권역 편집으로 그린 권역입니다(시험용 격자는 없앴습니다). 주문은 위치가 들어 있는 권역(세부권역 우선)에 속하고, 그 권역의 담당 기사(기사의 담당 권역, 메인 권역 우선)를 받습니다. 세부권역에 담당 기사가 없으면 상위 권역의 기사를 따릅니다. 경계가 없는 권역에는 주문이 들어오지 않습니다.
- API(`services/api`): 계정·세션(접근·갱신 토큰), 멤버십 기반 데이터 접근, 승인 흐름, 휴대폰 인증 발송 장부.
- API: Ours24 Job과 행을 읽어 주문으로 돌려줍니다(GET만).
- API: `POST /api/stop-sequence`가 기사 한 명의 정차지를 방문 순서로 정렬하고 도착 예상 시각·도로 선을 돌려줍니다. 경로 엔진(OSRM+VROOM, `infra/route/`)은 로컬 Docker로만 구동하며, `UPS_VROOM_URL`이 없으면 503입니다.
- API: 주소 저장소(PostgreSQL). 영문 원본, 한글 주소, 좌표, 정답지와의 비교 결과를 둡니다.
- API: 주문을 읽을 때 Ours24 행을 `delivery_task`에 남깁니다(고객 이름·전화번호 제외).
- API·웹: 기사 계정. 개발 관리자가 승인 탭의 활성 멤버에서 "기사로 지정"(센터 하나·기사 코드 하나)하면 역할이 `driver`가 됩니다(V13 `driver_account`). 기사 계정은 `/api/driver`와 `/api/me`만 쓰고, `GET /api/driver/route`로 그날 전송된 자기 노선(주소·운송장, 고객 이름 없음)을 받습니다.
- API: 배송 결과(V15). 기사가 정차마다 도착, 배송 완료(KB, 대면은 수령인 이름·비대면은 사진) 또는 UPS 예외 코드(시트의 41개)를 보고하고, 사진을 올립니다(`UPS_PHOTOS_DIR`의 파일). 웹 배차 내역의 타임라인에 도착·완료·예외와 현장 확인 사진이 나옵니다.
- API: 배차 저장(`POST /api/dispatches`, 관리자·개발 관리자)과 목록(`GET /api/dispatches`). 서버가 기사별 순서를 경로 엔진으로 계산해 계산한 값 그대로 저장합니다(V11: `dispatch_plan`, `dispatch_route`, `dispatch_stop`). 같은 센터·운영일을 다시 저장하면 이전 초안은 `REPLACED`가 됩니다. 웹의 배차에 "배차 저장"(관리자·개발 관리자, 센터 하나 선택 시)이 있고, 레일의 "배차 > 배차 내역"이 그날 저장한 배차를 최신 순으로 보여 줍니다(상태·기사·주문·미할당 수). 배차를 고르면 Detail에 기사별 노선이 나오고, 노선을 열면 저장된 값 그대로 타임라인·경로선·핀 순번을 보여 줍니다(`GET /api/dispatches/{id}`). 관리자·개발 관리자는 초안을 "노선 전송"(`SENT`, 센터·운영일당 하나, 이전 전송분은 `REPLACED`)하고, 초안·전송분을 "배차 취소"(두 번 눌러 확인)할 수 있습니다. 초안에서는 노선을 다른 기사에게 넘기고, 위치가 있는 미할당 주문을 노선에 더할 수 있습니다(더하면 그 노선의 순서를 다시 계산). 기사 앱으로 실제 전달은 아직 없습니다.
- API: 행정구역 경계(V18). 공개 행정동 경계(SGIS, vuski/admdongkor, CC BY 4.0)를 터미널 명령으로 넣고, 시·군·구와 일반구가 있는 시는 합쳐 만듭니다. 개발 DB에 2026-07-01 기준 행정동 3,558·시군구 256·시 13개가 있습니다. 읽는 API와 지도 표시는 아직 없습니다. 출처는 [infra/boundaries/README.md](infra/boundaries/README.md).
- 서비스 문: 주소 엔진이 쓰는 큐 읽기, 결과 쓰기, 정답지 읽기.
- 도구(`scripts`): Ours24 GET 검증, 개발 관리자 비밀번호 보관과 API 호출, 업로드 파일의 한글 주소 정답지 가져오기, 성남 센터 데모(센터·구역·기사·Job 센터·한글 주소) 설정.
- 데모: 2026-10-05 성남 센터가 개발 DB에 있습니다. 기사의 메인 구역과 담당 구역, 구역별 기사, 그날 주문(운송장 기준 한 건씩)과 한글 주소를 볼 수 있습니다. 한글 주소는 V-World로 좌표를 넣어 주문이 지도에 찍힙니다.
- 기사 앱(`apps/android`): 로그인(기사 계정), 그날 노선 타임라인, 정차 화면(도착·배송 완료 C/R 대면 이름 또는 비대면 사진·UPS 예외 코드). 사진은 앱 캐시에서 보내고 지웁니다.

아직 없는 것:

- 주소 번역·지오코딩 엔진의 동작. 자리는 `engines/address/`에 고정되어 있고 구현은 [이슈 #14](https://github.com/EVNSolution/clever-ups/issues/14)입니다.
- 관제 웹의 센터·구역·기사 관리 화면, 배차 결과 저장·노선 전송·배차 내역, Job의 센터를 나누는 규칙.
- 지오코딩의 주기적 자동 실행. 지금은 관리자가 한글 주소를 입력할 때(서버) 또는 `scripts/geocode_addresses.py`를 돌릴 때만 좌표가 들어갑니다. 개발용 V-World 키는 로컬 주소에 묶여 있습니다.
- 업로드 파일(xlsx) 내보내기, 고객 연락처의 출처.
- 기사 앱의 지도·오프라인 대기열·세션 유지·백그라운드 위치, Ours24로 배송 결과 보내기(POST, 별도 요청 전 금지).
- 타임라인의 완료 단계·현장 확인(기사 앱 보고가 필요), 경로 엔진 운영 배포, 기사 위치(GPS), 쓰기(POST) 방식의 Ours24 연동.
- 운영 배포, HTTPS(방식은 [docs/deploy.md](docs/deploy.md)에서 정함, 미구현), 비밀번호 변경·복구, 개인정보처리방침·위치기반서비스 약관.

검증하지 못한 것은 각 문서의 "미검증"에 적습니다. 실제 문자 수신은 휴대폰으로 직접 확인해야 합니다.

## 구조

```text
apps/web/        TypeScript + Preact + Vite. 지도 중심 운영 화면
apps/android/    Kotlin 네이티브 기사 앱
services/api/    Kotlin + Spring Boot 단일 애플리케이션, Flyway 마이그레이션
infra/route/     경로 엔진(OSRM + VROOM) 로컬 실행 파일. 지도 데이터는 커밋하지 않음
contract/        OpenAPI 계약. 모든 모듈의 공통 기준
engines/         API 밖에서 도는, 자주 바뀌는 부품. 위치와 구조는 소유자가 고정
scripts/         Ours24 검증, 비밀번호 보관, 가져오기 도구
tests/           Python 도구와 저장소 구조 테스트
docs/            구성 결정, 연동 검증, 참고 자료
```

## 실행과 검증

```bash
cd services/api && ./gradlew test detekt bootJar     # JDK 21
cd apps/web && npm install && npm run check && npm run dev   # Node 22.18+
python3 -m unittest discover -s tests
```

- API의 실행 방법과 환경 변수는 [services/api/README.md](services/api/README.md)에 있습니다.
- 웹 개발 서버는 `/api`를 `http://127.0.0.1:8080`으로 전달합니다.
- DB는 `UPS_DB_URL`이 있을 때만 켜지고, 테스트는 H2로 돌며 `UPS_TEST_DB_URL`을 주면 PostgreSQL로 돕니다.

## 프로젝트 경계

UPS 전용 웹·API·DB·실행 자원·배포·백업을 독립적으로 운영합니다. 백엔드는 하나의 애플리케이션입니다.

기존 DSV·K-FOOD(Shopify)의 Route Server에는 UPS 업무 로직을 추가하지 않습니다. 기존 운영 API, DB, 인증 정보, OSRM/VROOM 실행 인스턴스를 공유하지 않습니다.

재사용은 필요한 소스 코드와 연동 설정을 선별해 이식하는 것입니다. 이식하면 원본 경로·리비전·수정점·라이선스를 기록하고, 이후 수정·검증·배포는 UPS가 독립적으로 합니다. 원본 고객의 데이터와 비밀정보는 가져오지 않습니다.

## 재사용 후보

| 대상 | 후보 | UPS에서 따로 준비할 것 |
| --- | --- | --- |
| OpenFreeMap / MapLibre | 지도 초기화, 스타일, 마커·경로 표시 | 타일 제공 방식과 attribution |
| OSRM | 경로 geometry 요청 클라이언트, 국내 지도 실행 설정 | 전용 실행 환경, 한국 도로 데이터 |
| VROOM | 최적화 요청/응답 변환, 실행 설정 | 차량·주문 제약, OSRM 연결 |

- 지도는 OpenFreeMap 스타일과 MapLibre로 이미 동작합니다. 그 코드는 이 저장소에서 새로 작성했고, 아래 원본에서 복사한 파일은 없습니다.
- OSRM/VROOM은 이식하지 않았습니다. 후보 원본은 `EVNSolution/clever-route-server`의 리비전 `aff739cfc07a05dab1d5322ee4db072eb102f7ed`에서 확인했습니다.
  - `apps/delivery-api/src/modules/route-plans/osrm-route-geometry.client.ts`
  - `apps/delivery-api/src/modules/route-plans/vroom-route-optimizer.client.ts`
  - `infra/vroom/config.korea.yml`
  - `infra/compose/docker-compose.prod.yml`의 OSRM Korea / VROOM Korea 서비스 설정
- 이식하기 전에 UPS에서 동작하는지 검증합니다. 코드 이식만으로 지도 데이터나 엔진 실행 환경이 준비되지 않습니다.
- 주소를 좌표로 바꾸는 지오코딩 제공원은 엔진 담당이 정합니다.

## 기본 UI

지도를 메인 작업 화면으로 두고 기사·주문·구역을 좌측 Plot 탭에서 처리합니다. 목록을 고르면 좌측 옆으로 Detail이 확장되고 지도에 마커가 표시됩니다. 설정처럼 전체 화면이 필요한 기능만 지도 없는 페이지로 갑니다.

상세 계약은 [DESIGN.md](DESIGN.md), 모듈 구성은 [구성 결정](docs/architecture.md), 참고 자료는 [Mobbin 참고 문서](docs/references/mobbin/DESIGN.md)입니다. 이 참고 문서는 시각 스타일 분석이며 실행 가능한 컴포넌트가 아닙니다.
